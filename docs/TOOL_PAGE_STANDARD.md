# Tool Page Standard

Every tool page is a complete educational resource, not simply a utility.

Each page should contain:

---

## Hero

- Tool name
- One-sentence value proposition
- Privacy badge
- Input / Output interface

---

## Introduction

Explain:

- what the tool does
- why developers use it
- common workflows
- common industries

---

## How To Use

Provide step-by-step instructions.

Include keyboard shortcuts where appropriate.

---

## Interactive Examples

Include:

- simple examples
- advanced examples
- edge cases
- malformed input
- expected output

---

## Practical Use Cases

Real developer scenarios.

Examples:

- APIs
- Databases
- React
- Node.js
- DevOps
- Infrastructure

---

## Common Mistakes

Explain:

- incorrect usage
- misconceptions
- unexpected behaviour
- debugging tips

---

## Best Practices

Professional recommendations.

---

## Performance Notes

When relevant.

---

## Security Notes

When relevant.

---

## Language Specific Guidance

Whenever applicable explain behaviour in:

- JavaScript
- TypeScript
- Python
- Go
- Rust
- Java
- C#
- PHP
- SQL
- HTML
- CSS

---

## FAQ

Minimum 20 questions.

Questions should resemble Google People Also Ask.

---

## Related Tools

Cross-link naturally.

---

## References

Official documentation.

Never link to low-quality blogs when official specifications exist.
